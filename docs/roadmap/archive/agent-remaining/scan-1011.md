# scan-1011 (INBOX 862, Brief 99): the full functionality scan

Method: Playwright scripts per surface on a fresh data dir (first run, a 20-note burst, the offline queue, every Settings pane, every tab's controls, errors.js at 1440 and 390), against a stand-in OpenAI-dialect server that answers, answers slowly or never answers. Findings that were small and local are fixed (see CHANGELOG, four commits); these are not.

Open:
- **Filing against a model that never answers is serial and slow** (measured, a stand-in server that holds every request): a burst of 20 notes saved the way Capture saves them (`defer_filing`), 20 jobs queue on the model lane and each waits its own `FILING_MODEL_DEADLINE_SECONDS` (15 s) in turn. Settled after 20, 31, 51, 61 s ... 4 of 20 by 71 s, 6 of 20 by 91 s, about 300 s for all; 14 rows still said "Filing" at 91 s. CLAUDE standing rule (the owner, 0.3.31): a note takes "5-10 s at most". Steps: `python scratchpad/ui-sweeps/serve.sh 8879 /tmp/x`, set the provider to a server whose `/chat/completions` sleeps (a 10-line `http.server`), `POST /models/chat-model`, then `POST /entries {"content": ..., "defer_filing": true}` twenty times and poll `GET /entries` for `filing_state`. Recommended fix: a circuit breaker in `janitor._chat_within_deadline` (two deadline misses in a row opens it for 30 s: the next filings take the stand-in at once instead of waiting), and a `retry_stand_ins` job queued when it closes, so the stand-ins are asked again without a restart (today only the next launch retries them: `routes_models.warm_filing`). Not built because it changes when a slow-but-working model is asked and needs the owner's call on the 30 s.
- **A note created without `defer_filing` holds a database connection for the whole model wait.** Twenty such `POST /entries` at once against the stand-in (the API default is not deferred; MCP, scripts, importers and the agent's own create call it that way) filled SQLAlchemy's pool (5 + 10): `QueuePool limit ... reached, connection timed out` for 30 s, `POST /auth/unlock` and one `PUT /preferences` answered 500 until the model connection was cut. The page's creators now all defer (a lint, `test_every_note_the_page_creates_is_filed_in_the_background`), so the page cannot cause it; `create_entry` itself could release its session before `_file_entry_now` or the route could default `defer_filing` on. `src/memorymap/api/routes_entries.py:710` onward.
- **Text size "Small" puts phone tap targets under 44 px.** `--target-min: 2.75rem` (00-tokens-shell.css:530 and the 820 band) is in rem and the root is 14.5 px at Small, so every dock and sub-tab control measures 39.9 px at 390 wide (`touch.js`: 195 findings with Small, 0 targets covered or overlapping). At the default size touch.js found 0 under 44 on every surface it opened (measured on a fresh data dir). A px floor under `(pointer: coarse)` fixes it; the design call is whether Small should shrink hit targets (the owner's accessibility rule says no).
- **A server restart under an open page** shows the toast "Locked" with "Open the logs" and "Report this" when a setting is changed (the PUT is silent, so the lock screen is not drawn), and a note Save then says "Can't reach the MemoryMap server. Is it running?" although it is; reproduce by restarting uvicorn with the page open, then toggling any Settings, Appearance switch. `apiJson`'s `silent` path in app.js (`isLockout`) should show the lock screen once.
- **The Guide answers an off-topic question with the open tab's help, unlabelled.** "what is the weather today" asked from the Library returned "From the help: The Library is everything already made..." with no model running (`help_chat.topics_for` falls back to `TAB_TOPICS` when nothing is named, by design for "how does this work?"). A question that names nothing and is not a how-to deserves one line first ("The help does not cover that; here is what this tab does"). Reproduce: Settings, Help, ask it; `src/memorymap/ai/help_chat.py:2430` onward, with `tests/fixtures/help_questions.json` as the bank to hold.
- `A reminder needs text and a due time.` (shell-reminders.js:1528) is shown when only one of the two is missing; naming the missing one needs `tests/test_no_report_on_expected.py:40` changed with it.
- The notification bell and Activity count: not a defect, but a fresh launch with no model lists "Warming up the filing model" every launch (one row per page load, `warm-filing`). Consider showing it only when a model is reachable.
