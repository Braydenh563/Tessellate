# Tab-switch lag, INBOX 1433 (agent, 2026-10-29)

Method: Playwright, CDP `Emulation.setCPUThrottlingRate` 4, Tracing (`devtools.timeline` plus the stack category), 42 notes and two boards, `switchTab` to dashboard, notes, graph, timeline and library, 8 rounds each, port 8796. Style is the sum of `UpdateLayoutTree` per visit, in ms. Base is `f85b0fc`. The script is in the session scratchpad (`trace.js`, not committed).

## Numbers per tab (style ms per visit, layout ms per visit, style passes of 8 ms or more per visit)

| Tab | Before | After (3 runs, mean) |
| --- | --- | --- |
| dashboard | 374, 67, 10.9 | 279, 63, 6.3 |
| notes | 258, 61, 7.4 | 166, 46, 3.4 |
| graph | 169, 22, 5.1 | 128, 20, 2.2 |
| timeline | 182, 75, 8.5 | 111, 63, 3.5 |
| library | 167, 30, 5.0 | 103, 32, 2.3 |

Style time per visit fell 25 to 39 percent and the number of costly style passes roughly halved. Run to run spread is about 10 percent (the three "after" runs: dashboard 261, 266, 310).

## Causes found

- Hypothesis confirmed in part. Of 606 `:has()` selectors only four on body or :root were keyed on a tab's `.hidden` (graph-lazy.css `body:has(#tab-graph:not(.hidden))`, 10-responsive.css and 08-consistency.css `body:not(:has(#tab-chat:not(.hidden)))`, and the `.dock-fab` one). Each tab flip re-matched them. They now read `body[data-tab]`, which `revealTab` sets (navigation.js). The timeline's 115 ms style pass over 31 elements (an invalidation walk, not a big recalc) is gone.
- `graph.js` `initGraphDockHeightToken` read `getBoundingClientRect` inside its ResizeObserver, so a tab flip that hid the dock forced a 708-element style pass inside the callback (72 ms at 4x, 8 of 8 notes visits). It reads the entry's `borderBoxSize` now.
- `graph-canvas.js` `gcResize` did the same with `clientWidth` in its observer (129 ms at 4x on notes, once the graph dock fix exposed it). A 0x0 entry for the box returns early now.
- The forced style pass at `revealActiveTab` (shell-reminders.js:259, `scrollIntoView`) is the tab flip's own cost surfacing in its first reader, not an extra pass: 30 to 60 ms at 4x per tab on every run. Deferring it was tried by an earlier session and moves the cost, not removes it. Left alone.

## Lag log attribution

`app.js Response.json.then` now reads `app.js Response.json.then 912ms (forced layout 880ms) [apiJson /entries from notes-list.js loadNotes]`. lag-watch.js wraps `apiJson` once it loads (as status.js does), reads the first stack frame outside the plumbing, and stamps each answer; the frame line lists the answers (up to three) whose time falls inside the long frame. Nothing is added to the boot scripts. Test: `tests/test_diag_report.py::test_a_long_frame_in_apijsons_continuation_names_the_path_and_the_awaiting_caller`. Answers that arrive before lag-watch.js loads (about the first three seconds) carry no caller.

## Guard

`tests/test_css_body_has.py::test_no_page_wide_has_keyed_on_a_tab` fails on any `:has(#tab-...)` or `:has(.tab-page...)` under body, :root or html. The `body:has` allowlist lost its graph entry. Existing tests that quoted the old selectors (`test_phone_notes_audit`, `test_round2_sweep_fixes`, `test_graph_toast_1306`) changed text only; their assertions are the same.
