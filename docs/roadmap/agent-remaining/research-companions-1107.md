## 1. Desktop pets and mascots: what they do, how they find edges

### 1.1 Per-product findings

- **Shimeji-ee** (the genre's reference; zlib/libpng-style licence, bundled JNA is LGPL: [readme](https://github.com/gil/shimeji-ee/blob/master/originalreadme.txt)).
  - Window logic read from source ([WindowsEnvironment.java, frankkienl fork](https://raw.githubusercontent.com/frankkienl/shimeji-ee/master/src_win/com/group_finity/mascot/win/WindowsEnvironment.java)): no `EnumWindows`. It walks z-order from the foreground window with `GetWindow(GW_HWNDFIRST/NEXT)`, skips invisible and iconic windows, returns null if a visible window is maximised, accepts only "IE" windows matched by title list (`windows.txt`) or class name `IMWindowClass`, and caches results. Only the first (active) one is a surface. Edge = `GetWindowRect`, trimmed by `GetWindowRgn` box. It can move the window (`MoveWindow`) so it can throw or carry it. Work area = one global `SPI_GETWORKAREA` per tick; no per-monitor loop, no DWM frame bounds, no cloak check, no taskbar-specific code (any taskbar exclusion comes from the work area).
  - Structure: an actions file (what it can do) and a behaviours file (when), actions and behaviours can be sequences of others, every behaviour needs an action, required actions `ChaseMouse, Fall, Dragged, Thrown` ([chaoskagami fork readme](https://github.com/chaoskagami/shimeji-ee)). This is a weighted-transition state machine with conditions, authored as data.
- **Desktop Goose** (closed source; Sam Chiet): wanders, chases the cursor, opens Notepad and writes notes, drags memes and leaves mud tracks onto the desktop ([Neowin](https://www.neowin.net/news/you-can-finally-have-a-goose-wreak-havoc-on-your-desktop-like-youve-always-wanted/), [Windows Central](https://windowscentral.com/you-can-now-download-untitled-goose-ruin-your-desktop)). Mud tracks and memes appear on one FAQ page only: **unverified**. What matters for us: its personality comes from props that live on the desktop (notes, memes, tracks) and from the cursor, not from window edges.
- **BonziBuddy / Microsoft Agent (Clippy, Merlin, Genie)**: the animation format is the lesson. Each animation has optional **exit branches** (the engine plays the Return animation automatically before the next one, so no pop: [Merlin animation list](https://learn.microsoft.com/en-us/windows/win32/lwef/microsoft-agent-animations-for-merlin-character)); **branching** per frame gives up to three other next frames by probability, which also builds endless loops ([Creating animations](https://learn.microsoft.com/en-us/windows/win32/lwef/creating-animations)); idle animations are tiered (IdlingLevel1 to 3, level 3 is "falls asleep" or "listens to music": [Genie list](https://learn.microsoft.com/en-us/windows/win32/lwef/microsoft-agent-animations-for-genie-character)). Browser port: clippyjs (community; licence not checked).
- **VPet-Simulator** (C#, WPF): open source, Apache-2.0 contributions, mod types for animations, items, text, themes and code plugins, Steam Workshop; animation files carry credit and no-resale terms ([repo mirror](https://github.com/xiaoyaoshengy/VPet)). The upstream licence text was not read: **unverified**. Take: an item and food economy plus a plugin boundary.
- **Bongo Cat** (Apache-2.0 per GitHub metadata, [ayangweb/BongoCat](https://github.com/ayangweb/BongoCat)): reacts to global keyboard and mouse input. Take: input-reactive animation is the cheapest "it sees what I do" feel. Details of its implementation not read.
- **eSheep** (MIT; web port GPL-3.0 per GitHub metadata: [desktopPet](https://github.com/Adrianotiger/desktopPet), [web-esheep](https://github.com/Adrianotiger/web-esheep)). One XML file holds header, a sprite sheet grid (equal cells, base64) and animation nodes; movements and **child** spawns are data ([XML intro](https://github.com/Adrianotiger/desktopPet/wiki/XML%5CIntroduction)). Child-spawn mechanics not read: **unverified**.
- **Neko / oneko**: 32 sprites, 8 by 4; chases the cursor, scratches the screen edge, yawns, sleeps, itches, wakes with a start; stops and sits when the cursor stops ([oneko page](https://onekoshima.pages.dev/oneko.html), [man page](https://www.mankier.com/1/oneko)). Take: the cursor is a character (a mouse to catch), and the wall scratch is a cheap edge interaction.
- **Desktop Mate** (Steam, 3D models): sits on top of a window you drop it on, jumps window to window, plays with the cursor ([Steam](https://store.steampowered.com/app/3301060/Desktop_Mate/)). Real-time 3D skeleton, so no sprite frame steps. No source found on its edge detection or taskbar handling: **unverified**.
- **Rusty's Retirement**: sits under other windows at the bottom of the screen ([GamesRadar](https://www.gamesradar.com/like-an-idle-stardew-valley-this-cute-farm-sim-sits-at-the-bottom-of-your-screen-while-you-do-other-things-and-already-threatens-my-productivity)); implementation not documented. Take only the z-order idea (see row T5).
- **macOS pets / WindowPet**: nothing usable found in the searches run; not covered.

### 1.2 Windows techniques (what is documented)

- **Taskbar.** `SHAppBarMessage(ABM_GETSTATE)` returns the autohide and always-on-top flags; `ABM_GETTASKBARPOS` the taskbar rectangle; for the usable area Microsoft says call `GetMonitorInfo` (`rcWork`), because other appbars also shrink it ([SHAppBarMessage](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shappbarmessage), [ABM_GETSTATE](https://learn.microsoft.com/en-us/windows/desktop/shell/abm-getstate)). `ABM_GETAUTOHIDEBAREX` finds the autohide bar per monitor edge. With autohide on, `rcWork` may not exclude the taskbar ([MS Q&A](https://learn.microsoft.com/en-us/answers/questions/760561/how-do-i-find-the-size-of-the-available-display-ex)). Third-party "hide the taskbar" tools hide `Shell_TrayWnd` and often also reset the work area, but a tool that does only the first leaves `rcWork` excluding a taskbar nobody can see ([AutoHotkey thread](https://www.autohotkey.com/boards/viewtopic.php?t=60866)). Whether a given hider resets the work area was not established: **unverified**. This is the likely cause of the owner's 1692 (a) "still sits at taskbar height".
- **Which windows count.** `EnumWindows` plus: visible, not cloaked (`DWMWA_CLOAKED`, needed for other virtual desktops and suspended UWP), not `WS_EX_TOOLWINDOW`, owner-chain rule, and UWP windows are hosted by `ApplicationFrameHost` so the cloak check is the reliable filter ([Raymond Chen 2020](https://devblogs.microsoft.com/oldnewthing/20200302-00/), [PowerToys Alt-Tab code](https://gitverse.ru/githubmirror/PowerToys/content/main/src/modules/AltWindowCycle/AltWindowCycle.cpp)). Visible frame = `DWMWA_EXTENDED_FRAME_BOUNDS`, not `GetWindowRect` (the latter includes the invisible resize border).
- **Following windows without polling.** `SetWinEventHook` (out-of-context) with `EVENT_OBJECT_LOCATIONCHANGE`, `EVENT_SYSTEM_MOVESIZESTART/END`, `EVENT_SYSTEM_FOREGROUND`; filter by `idObject == OBJID_WINDOW`, because the location event is also raised for the caret and cursor and a wide hook costs the hooked app ([community thread](https://kaweah.freedombox.rocks/kiwix/stackoverflow.com_en_all_2023-11/questions/15750038/detect-hook-window-move-drag-of-other-external-processes), [Excel-DNA PR showing the lag](https://github.com/Excel-DNA/IntelliSense/pull/130/files)). Community sources only; the Microsoft pages were not fetched.
- **Multi-monitor and DPI.** Per-monitor-v2 awareness plus `MonitorFromPoint` and `GetDpiForMonitor` per work area is the correct pattern; Shimeji-ee uses one global rectangle.

### 1.3 Behaviour and AI systems in pets

Shimeji: data-driven weighted state machine. Agent: probabilistic frame branching plus tiered idles plus exit branches. eSheep: XML data plus children. VPet: needs plus items plus plugins. Goose: props and cursor. None of them is a utility or planning system; ours (needs plus weighted choice, `behaviour.Mind`) is already more than the genre standard. The AAA bar in section 2 is the one to compare against.

## 2. NPC behaviour and animation: what professionals do

- **Utility AI / IAUS.** Score every action by several considerations, each a raw value pushed through a response curve into 0..1, multiplied together with a compensation factor; pick best, weighted-random, or weighted-random among the top n ([Dave Mark, gameai.com](https://gameai.com/iaus.php), [slides](https://api.sambuz.com/doc/improving-improving-ai-decision-modeling-ai-decision-ppt-presentation-788939)). Curves and many considerations are the point; a single linear need is not IAUS.
- **GOAP / F.E.A.R.** A three-state FSM (Goto, Animate, UseSmartObject) and an A* planner over actions with preconditions and effects ([Orkin, GDC 2006](https://gdcvault.com/play/1013459/Three-States-and-a-Plan), [slides](https://pages.cs.wisc.edu/~dyer/cs540/handouts/gdc2006_orkin_jeff_fear.pdf)). The lesson is that the "intelligence" is data (actions and goals), and animation is a leaf state.
- **The Sims.** Needs decay; objects advertise what they satisfy (smart objects); a Sim scores interactions by motive deficit ([GMTK summary](https://gameindustrylibrary.com/documents/gmtk-the-genius-ai-behind-the-sims), [smart objects notes](https://blueagate.vercel.app/study-notes/game-development/artificial-intelligence/smart-objects)). Secondary sources only. Key move: the world holds the affordances, so adding an object adds behaviour with no agent code.
- **Behaviour trees.** Sequence, selector, parallel, random-weighted "lotto", guards that interrupt a running branch, decorators, running state across ticks ([mistreevous docs](https://nikkorn.github.io/mistreevous/docs.html), MIT per [GitHub](https://github.com/nikkorn/mistreevous)).
- **Procedural animation / secondary motion.**
  - Disney's twelve principles (anticipation, follow-through and overlapping action, slow in and out, squash and stretch, secondary action): [illustrated primer](https://laughingsquid.com/the-illusion-of-life-the-12-basic-principles-of-animation-illustrated-by-a-small-emotive-cube/), [summary](https://subtraction.com/2014/05/04/the-12-principles-of-animation).
  - Second-order dynamics with frequency f, damping zeta and response r: r below 0 gives anticipation, above 1 overshoot; stable semi-implicit step ([t3ssel8r summary](https://recapio.com/digest/giving-personality-to-procedural-animations-using-math-by-t3ssel8r), [spring_motion crate](https://docs.rs/spring_motion)). One cheap primitive covers lag, overshoot, anticipation.
  - Verlet and position-based dynamics for tails, hair, cloth: [Müller et al. PBD](https://diglib.eg.org/items/deb0a7a1-2ddf-496f-889a-fe0df1feeb73) (credits Jakobsen's Verlet approach); [verlet-js](https://github.com/yangdi/verlet-js) (MIT, particles plus distance and angle constraints, cloth helper; no hair or tentacle example found).
- **Blending and state machines (Rive, Spine, Live2D, Lottie).** Rive: states, blend states, Boolean/Number/Trigger inputs, **parallel layers** (hover layer plus blink layer), pointer listeners ([Rive inputs](https://www.rive.app/docs/runtimes/inputs), [Rive blog](https://rive.app/blog/state-machines-make-iteration-a-breeze-for-designers-and-developers), [glossary](https://github.com/UpstandPlatform/OpenRive/wiki/Glossary)). Rive's own docs now prefer Data Binding over inputs. Live2D: auto-blink and auto-breath as additive parameter layers, physics for hair ([auto blink](https://docs.live2d.com/en/cubism-sdk-manual/autoeyeblink)); the physics page was not found: **unverified**. Lottie: `dotLottie` has state machines, MIT ([dotlottie-web](https://github.com/LottieFiles/dotlottie-web)).
- **Gaze and blink.** Lee, Badler and Badler "Eyes Alive": saccade magnitude, direction, duration, velocity and inter-saccade interval drawn from eye-tracking statistics, separately for talking and listening ([paper](https://www.cis.upenn.edu/~badler/papers/EyesAlive.pdf), [SmartBody implementation](https://smartbody.ict.usc.edu/HTML/documentation/SB/Eye-Saccade_8552851.html)). Paper's blink timing not read: **unverified**.
- **Idle variation.** Agent's tiered idles (above); Live2D additive breath and blink.
