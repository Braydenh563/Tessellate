# row21-1109: surfaces as templates (audit 1031 row 21)

## Design

Measured on head ad5ab98 (`index.html` parsed, elements outside any `<template>`):
5,521 live of 7,948 (the Settings body, 2,405, is already a template). The rest by
surface: board canvas `#wb-canvas-view` 1,741 (shown only with a board open),
Notes 579, Documents 470, Graph 398 (its options panel 249), Chat 220, Timeline
153, OCR workspace 132, Reminders 125, shortcuts sheet 85, meeting sheet 61.

- **One mechanism, not two.** settings-body.js's build-on-first-need becomes
  generic: `<template data-surface="NAME">`, `surfaceBuild(name)` stamps it once
  (and reruns the help sweep on what arrived), `onSurface(name, run)` queues a
  wiring that needs its elements, `surfaceFind(id)` is `$`'s fallback so a caller
  that asks early still gets the element. Settings is `data-surface="settings"`;
  its old names go (global-name cap: four names out, four in).
- **Markup stays in index.html.** A template keeps every id, `data-help-for`,
  `aria-*` and chord title greppable, so `test_frontend_ids`, CODEMAP, the
  reveal table and the manual parity tests read it unchanged. Lazy-built DOM
  in JS was rejected: it would move ids out of the page and fork the copy.
- **The shell stays live.** The template sits inside the surface's root
  (`#wb-canvas-view` stays in the page), so checks of "is the board open"
  (`wiring.js`, `phone-shell.js`, `status.js`, the companion) never stamp.
- **When it stamps.** At the open (`wbShowCanvasView`, `initWhiteboard`), or the
  first `$` of one of its ids. Wiring that ran at bundle load against canvas
  elements (`onDomReady` blocks and top-level `getElementById(...).on` lines in
  whiteboard*.js) moves to `onSurface("board", ...)`; a lint holds it.
- **Not moved:** first-paint surfaces (top bar, lock, dashboard, the landing
  tab), the dock bars, anything a keyboard shortcut reads at boot. Order: board
  canvas (1,741), then the overlays opened by one function (OCR 132, shortcuts
  85, meeting 61), then the graph options panel (249) if its wiring is bounded.
- **Ratchet.** `tests/test_boot_diet3.py` counted template contents too, so a
  template could never lower it, against its own stated intent; it now counts
  the elements parsed into the live page.
