## Design: routes_whiteboard.py (6,344 lines)

Layers in import order (`api/wb_*.py`); the hub includes each layer's `APIRouter` in the order its routes had, so every URL, operation id and the route order are unchanged (`app.routes` and `app.openapi()` dumped before and after: identical).

1. `wb_model`: limits, kinds, layouts, theme fields, comment/node/sketch/object models and state helpers.
2. `wb_board`: board lookups, the state route, settings, theme, layers, background, `BoardOut`.
3. `wb_preview`: the library card, its cache, the thumbnail routes and `media_router`.
4. `wb_boards`: list, images, create, duplicate, rename.
5. `wb_items`: node, sketch, object routes, save-many, delete.
6. `wb_tree`: a map's tree, references, styling.
7. `wb_export`: map writers and the export route.
8. `wb_import`: map readers and placing (before `wb_map`, whose paste route calls them).
9. `wb_map`: a map's node routes.
10. `wb_make`: propose, generate, import board.

Two blocks moved out of file order to break a cycle: `_board_entry` to `wb_board` (the thumbnail code in `wb_preview` calls it) and `_flatten_parsed` to `wb_import`.
