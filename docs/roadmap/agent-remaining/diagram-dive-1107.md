# Diagram builder deep dive (INBOX 1692, 2026-11-07): research, audit, ranked build list

Research and audit only; no app code changed. Branch `agent/diagdive-1107` (from `claude/next-queue-1102`, head 4b2020f3). Server: `serve.sh 8798`, fresh data dir. Sweeps were one-off scripts in the session scratch dir (untracked); every number below is from one of them, named in brackets: [open] first-run and controls, [build] keyboard build, [drag] handle drags and frame times, [src] source and errors, [kinds] kind bar on the page and in the dialog, [dock] dock overlap, [tab] Tab order, [m390] phone, [ct] contrast, [perf] 4x CPU, [exp] export and Done. Light and dark were both run at 1440; 390 was run light only; 4x CPU through CDP `Emulation.setCPUThrottlingRate`.

Owner words (1692): "still a pain to use and learn and it just doesnt feel nice or satisfying to use". Standing: UX first, grade "we have it" against the best, not as done because something exists.

Other measured facts:
- Frame times (rAF gaps), 1440, 1x: typing 4 blocks p95 16.7 to 50 ms, worst 183 ms (the picture redraw); drag to connect p95 16.7 ms. 4x: open p95 417 ms, worst 1,033 ms; typing p95 66.7 ms, worst 100 ms [perf].
- Controls: 29 in the empty dialog, 39 with two boxes. Under 44 px: 27 and 39 respectively (28 px dock buttons, 32 px kind and header buttons). Under WCAG 2.2 AA minimum (24 px) in size: only the split handle's 13 px width (it has an arrow-key alternative, so it passes the dragging rule). No unlabeled control; no label-in-name mismatch (every visible text is inside its accessible name) [open].
- Contrast: after fixing my own colour parser (it misread `color(srgb ...)` backgrounds, which produced six false 1.29:1 results in light), no text below 4.5:1 in light or dark at 1440 in the empty and two-box states [ct]. Not measured: icon-only buttons (3:1), focus ring contrast, text inside the rendered SVG, the dimmed "Describe it".
- Top bar wrap (1661): the flowchart dock is one row at 1440 in both themes and 390 (rows 1); at 390 the dock overflows the dialog by 18 px (the `...` button's right edge 384, dialog 366, dialog scrollWidth 359 > 340) [m390]. The kinds' docks are not one row (DD-2).
- Focus: opens on "Add a box" (good). Focus stays inside the dialog over 24 Tabs (no escape, no trap loop failure). Escape closes the dialog and returns focus to the opener; with unsaved blocks both Escape and Cancel ask "Close without keeping your changes?" (Keep editing / Discard changes) [tab].
- Tab order is DOM order, not visual: Add a box, Type a name, Draw an arrow, Start from an example, Start from a template, the split handle, the picture, Canvas, Blocks, Source, Open existing, Cancel, Done, the move grip, Minimise, Close, the four kind buttons, then the dock's first button at stop 20 [tab]. A keyboard user needs 20 Tab presses from the open focus to reach Add box, 16 for the kind bar, and shift-Tab 4 to reach the footer buttons that come first.
- Picture and screen readers: the picture is a focusable figure whose arrow keys only pan; it never selects a node. The `img` alt is the single word "Flowchart". A polite live region speaks status ("Renamed to Check.") but also "The whole diagram is in view, so there is nothing to move" every time the figure is focused [tab].
- Source pane: a plain textarea, 480 x 599 px, no line numbers, no highlight, no gutter marker, spellcheck off, aria-label "Mermaid source" [src].
- `prefers-reduced-motion`: no rule in diagram-lazy.css (grep: 0 matches), while the picture pans and zooms.
- Stray console error on every boot: `afterFrames is not defined` at shell-reminders.js:707, from a MutationObserver (the function lives in dashboard.js:1966, a lazily loaded file). Found, not fixed, not diagram code; it runs when a tab switch mutates the DOM before the Dashboard script loads.
