## Row D, Linux (built)

- `overlay/xlib.py` (ctypes over libX11, Xext, Xrandr, Xss; no python-xlib, which the app does not ship) is the one X object, `XConn`; `overlay/x11.py` has the backend functions the runner calls (`monitors`, `windows`, `notification_state`, `last_input_age`, `dpi_at_point`, `animations_enabled`) and `X11Host`, the Linux `OverlayHost` (a `select` loop on the X socket and a wake pipe: no polling). `OverlayRunner(backend=...)` picks `win32` or `x11` (by the connection it is given, else the platform); engine, sprites and perches are untouched.
- Window: override-redirect (no frame, no taskbar entry, no focus, placed exactly, may tuck behind an edge) on a 32-bit ARGB visual; input shape cut to alpha >= 8, plus the bounding shape where no compositor runs; pointer grabbed while dragged; raised on show and 0.2 s after `_NET_CLIENT_LIST_STACKING` changes (an event, since an override-redirect window is not kept on top by the window manager).
- EWMH: work area = monitor minus panel struts (`_NET_WM_STRUT_PARTIAL`, per monitor), else `_NET_WORKAREA` of the current desktop; window tops from `_NET_CLIENT_LIST_STACKING` with `_NET_FRAME_EXTENTS`, hidden/maximised/fullscreen state, window type, desktop, pid; a `_NET_WM_STATE_FULLSCREEN` top window hides the figure. Dpi = `Xft.dpi`, else `GDK_SCALE`.
- Wayland (`XDG_SESSION_TYPE`/`WAYLAND_DISPLAY`) or no display: `overlay_support()` says why, the card window stays and its right-click menu shows the one-line note; `TESSELLATE_OVERLAY_X11=1` tries XWayland. `work_area()`/`monitor_areas()` read the X server on Linux, so the quick panel avoids the panel/dock.
- Help: the Guide topic `desktop-companion` (1856 of 1900 characters) and the Settings popover say what Linux supports.
- Measured on Xvfb 1024x768 and 1280x800 (real server, real ctypes, no window manager): frame 130x148 px window, drawn pixels bbox 87x109 inside it (the clear part shows the root, not black); input shape bitmap 640 bytes for 60x80, row 40 bits `00fcffffffff0300`; XTest click on the figure gave one `left` click with box (632, 689, 78, 110); a click at (50, 50) gave none (click-through); a 12-step drag gave `held` at (765, 541) and a throw (`fly`) on release; a window moves from (100, 200) to (300, 400) as asked. Tests: `tests/test_overlay_x11.py` (35, fake X plus one Xvfb test that skips when Xvfb is not installed), the runner parametrized over both hosts.
- Merge note: the earlier rows were merged into this branch; `test_the_nebula_veil_is_the_same_in_every_frame_of_the_idle_cycle` follows the re-rendered frames (raw change 830 to 1220 before, about 115 now; the bound is under 200 and the loader must not undo it; said in the test).
