# a31i-1103: INBOX 1592, the dashboard's Quick capture is the Notes composer

Harnesses are untracked, in scratchpad a31i/ (m.js before and after, d.js the dashboard flow, atl2.js Atlas parked where the card opens, cost.js render cost, dbg.js Atlas state).

## Done

- One composer: `renderQuickCaptureWidget` (dashboard.js) mounts `captureBar()` (notes-list.js, a copy of the Notes bar's row, no ids; the static bar is wired by the same function). `openCaptureCard` moves the one card into the bar used (`captureCard.place`), a redraw hands an open card to the new bar (`captureCard.adopt`). The old textarea, its Save and its save code are gone.
- Swatch row: one row, no wrap, 24px dots (`--swatch-dot`), scrolls only when narrower than its content (capture-card-lazy.css). Notes picker 66px to 41px at 1440, 145px to 57px at 390.
- Atlas: `captureCard.settle()` (after open, close, mode, colours, pictures, suggestions) scrolls the card into view and fires `mm:controls-changed`, which avatars.js turns into an index reset and one look. First try (a ResizeObserver) was a new wake source and typeof guards; the event costs neither.
- Tests: tests/test_dashboard_capture_composer_1592.py; E2E spec in capture-filing.spec.js (not run here); pinned selectors moved from ids to classes (1479, a30s), test_lazy_retry and test_unslop_1103 follow the code.
- Global names: base was already 9707 against a cap of 9706; this change is net zero (captureBar added, captureCardHead and captureCardNeedsConnection folded in).
