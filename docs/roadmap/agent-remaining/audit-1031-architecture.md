## What is already good

- The shape is enforced by tests, not by prose: 21 ratchet and lint tests (load order, global scope, complexity, cycles, boot budget, CSS braces, ids, recipes, plan hygiene, README freshness), and the `data-help-for` and Guide parity lints keep help beside the UI.
- Single `ConfigManager` and `DatabaseManager` per process (principle 5) holds; the suite found no second constructor.
- Every provider runs behind one `provider.py` with a fake transport in tests (principle 7); the suite needs no model.
- The lazy bundles exist and are ordered with reasons (`app.js:1870` to `:1900`); the fix for PF4 is a policy change, not a new mechanism.
- Events (`core/events.py`) are one bus with a spec test; jobs are the exception, not the rule.

## Not verified

- Runtime coupling under a real model (every provider on a fake transport); the desktop launcher and the MCP server were read by the harness audit, not here.
- The ORM-in-routes count is a grep (`session.query(` and `select(`); a hand read of two routers (`routes_entries.py`, `routes_files.py`) agreed with it, the other 61 were not read.
